## 框架与设计思路

### 1. 流水线

```text
Plan → Fetch（HTTP / Playwright / 云 / MCP）
  → Extract（patch → template → rule → llm → heuristic）
  → Quality Gate → Retry
```

**思路**：抽取优先级从**确定性高**（站点 patch）到**确定性低**（LLM）降级 — 成本与稳定性权衡。

### 2. 通道选择

- HTTP + cheerio：静态页首选，快且便宜  
- Playwright：动态渲染、反爬、需登录  
- **seed_urls**：总管传入种子 URL，精抓而非盲搜  

### 3. vs Lobster_Agent

| | Extractor | Lobster |
|---|-----------|---------|
| 范式 | 列表页、字段抽取 | GUI 点击、验证恢复 |
| 难度 | 结构化输出 + 质量门禁 | 候选元素 + verify/recover |

## 算法与技术模式

| 模式 | 说明 |
|------|------|
| **Quality Gate** | 条数、字段完整性、schema 校验 |
| **Retry with Feedback** | 门禁失败带原因重规划 |
| **Async Queue** | 长任务 BullMQ 解耦 |
| **SERP Fallback** | 无 seed 时搜索引擎兜底 |

---

## 提示词与 LLM 工程

- **Task Planning**：输出 URL、字段、分页策略的结构化 plan  
- **LLM Extract**：仅在前序规则失败时使用，prompt 含 HTML 片段 + 目标 schema  
- 站点 `patches/sites/*.json` 是 **few-shot / 规则** 的替代，更稳
